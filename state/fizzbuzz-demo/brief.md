# Бриф: fizzbuzz-demo

## Цель

Тестовый прогон полного цикла agent-factory (intake → delegate → verify →
git commit → report) на маленькой, полностью объективно проверяемой задаче.

## Объём

Входит: `fizzbuzz.py` с функцией и точкой входа, `test_fizzbuzz.py` с
unit-тестами. Не входит: CLI-аргументы, веб-интерфейс, зависимости кроме
stdlib и pytest.

## Задачи

### Задача 1 — fizzbuzz.py

Создать `fizzbuzz.py` в корне репозитория:
- функция `fizzbuzz(n: int) -> str`: `"Fizz"` для кратных 3, `"Buzz"` для
  кратных 5, `"FizzBuzz"` для кратных и 3, и 5, иначе `str(n)`.
- при запуске как скрипта (`python fizzbuzz.py`) печатает `fizzbuzz(n)` для
  n от 1 до 100 включительно, по одному значению в строке.

**Критерий приёмки (проверяется командами):**
- `python fizzbuzz.py | wc -l` = `100`
- строка 7 = `7`, строка 9 = `Fizz`, строка 10 = `Buzz`, строка 15 =
  `FizzBuzz`, строка 100 = `Buzz`

**Исполнитель:** builder (создание файла).
**Файлы:** `fizzbuzz.py` (новый, корень репозитория).

### Задача 2 — test_fizzbuzz.py

Юнит-тесты (pytest) на `fizzbuzz()` из задачи 1: минимум случаи n=1
(обычное число), n=3 (Fizz), n=5 (Buzz), n=15 (FizzBuzz).

**Критерий приёмки:**
- `python -m pytest test_fizzbuzz.py` завершается с exit code 0.
- минимум 4 отдельных assert/тест-кейса на перечисленные случаи.

**Исполнитель:** builder (создание файла).
**Файлы:** `test_fizzbuzz.py` (новый, корень репозитория). Зависит от
результата задачи 1 (импортирует `fizzbuzz` из `fizzbuzz.py`) — выполняется
последовательно после задачи 1, не параллельно.
