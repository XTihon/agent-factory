---
name: verify-task
description: Проверяет одну выполненную задачу и обновляет её статус. Сразу после того, как рабочий агент вернул результат.
---

1. Возьми критерий приёмки задачи из state/<slug>/brief.md.
2. Вызови qa-reviewer с этим критерием и результатом на проверку. Если в
   репозитории уже есть коммиты — передай ему диапазон для git diff (последний
   relevant-коммит..текущее состояние) вместо просьбы читать файлы целиком.
3. PASS → отметь задачу verified в status.md, затем сделай git-коммит
   (пункт 11 в orchestrator.md).
4. FAIL → увеличь счётчик попыток; если попыток ≤ 4 — верни исполнителю
   конкретные замечания и повтори; если попыток > 4 — отметь needs-human с
   кратким описанием причины и переходи к следующей независимой задаче, не
   блокируя весь проект.
