# agent-factory

Универсальная система для выполнения проектов силами агентов. Скидываешь ТЗ,
данные и файлы в `inbox/`, ведущий агент разбирает задачу, делегирует нужным
рабочим агентам, независимо проверяет результат и доводит проект до
готовности циклом — без ручного ведения на каждом шаге.

## Карта

```
inbox/<slug>/          ← сюда кладёшь материалы по проекту
state/<slug>/brief.md  ← разбор задачи: цели, задачи, критерии приёмки
state/<slug>/status.md ← живой статус выполнения (память цикла)
output/<slug>/         ← финальный результат + report.md
.claude/agents/        ← оркестратор, qa-reviewer, builder, researcher, writer
                          (+ новые агенты, которых оркестратор создаёт по ходу)
.claude/skills/         ← start-project, intake, verify-task, final-report
.claude/hooks/          ← PreToolUse guard-скрипты
```

## Жёсткое правило

Ведущий агент (`orchestrator`) **никогда** не делает специализированную
работу сам и **никогда** не закрывает задачу без независимой проверки
агентом `qa-reviewer`. Это правило закреплено не только текстом промпта
оркестратора, но и хуками в `.claude/hooks/` — они блокируют запись файлов
реализации и прямой запуск сборки/тестов из-под оркестратора. Хуки — это
эвристики по regex, а не песочница: страховка от типичных ошибок, не
гарантия безопасности.

## Git

После каждой verified-задачи оркестратор делает git-коммит. Полная история
проекта — в `git log`, диффы задач — в `git diff`.

## Полный протокол

См. `.claude/agents/orchestrator.md` и скиллы в `.claude/skills/`.
