## Что показал тест системы

- Цикл intake → delegate (builder) → verify (qa-reviewer, независимая
  сессия) → git commit после каждой verified-задачи отработал как описано в
  `.claude/agents/orchestrator.md`.
- Замечание по хозяйству: первый прогон pytest оставил `__pycache__` в
  рабочей директории, который случайно попал в коммит задачи 2 — добавлен
  `.gitignore` и коммит `chore: ignore __pycache__`. В реальном прогоне это
  тоже стоит держать в виду: builder/qa-reviewer запускают код в рабочей
  директории репозитория, артефакты выполнения (кэши, `.pyc`, временные
  файлы) нужно игнорировать через `.gitignore`, а не чистить руками после
  каждой задачи.
- Нативный headless-прогон через `claude -p --dangerously-skip-permissions`
  не сработал в этом окружении: флаг bypass словил классификатор автономных
  действий родительской сессии, а без него дочерний процесс не смог сам
  авторизоваться (OAuth не наследуется дочерним процессом). Этот прогон
  сделан вручную поверх тех же ролевых файлов (`.claude/agents/*.md`) через
  `Agent` из родительской сессии — логика проверена, но не то же самое, что
  автономный `/goal`-цикл живого оркестратора в отдельном терминале.
